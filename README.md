# 🐌 Расширения TurboWarp

Каталог расширений для [TurboWarp](https://turbowarp.org/) в стиле «Ули»: официальная галерея + галереи сообщества.

> ⚠️ **Предупреждение:** расширения TurboWarp выполняются без песочницы и **могут содержать вредоносный код**.
> Официальная галерея проверяется вручную, остальные источники — нет.
> Используйте на свой страх и риск и читайте код перед запуском.

## Сборка

Всё воспроизводимо из исходных галерей:

```bash
python3 update.py    # collect.py -> fetch_ids.py -> build_data.py
```

| Скрипт | Что делает | Выход |
|---|---|---|
| `collect.py` | тянет каталоги со всех настроенных галерей (новый источник добавляется, только если приносит хотя бы одно новое расширение) | `turbowarp_extensions.json` |
| `fetch_ids.py` | скачивает каждый `.js` и достаёт зарегистрированный `id` расширения (понимает UTF-16) | `extension_ids.json` |
| `build_data.py` | объединяет дубли по `id` (fallback — по имени) и назначает категории | `extensions.json` |

Запустить по отдельности тоже можно: каждый скрипт читает пути из `TW_RAW` / `TW_IDS` / `TW_CACHE` (по умолчанию — рядом со скриптом). Кэш скачанных `.js` — `.ext_cache/` (в `.gitignore`).

⚠️ `fetch_ids.py` скачивает сотни расширений; для полноценной работы `collect.py` (dashblocks) нужен `node` в `PATH`.

## Обновление каталога через GitHub Actions

Workflow «Обновление каталога» запускается каждый понедельник в 04:17 UTC и вручную через **Actions → Обновление каталога → Run workflow**. Плановые запуски GitHub выполняет только на ветке по умолчанию; для ручного запуска выберите ветку с этим workflow.

Workflow собирает свежие данные во временный каталог, сравнивает записи галерей с сохранённой базой и публикует отчёт в Summary и три JSON-файла вместе с отчётом в артефакте `catalog-update` (хранится 30 дней). При изменениях workflow проверяет данные и коммитит три JSON-файла в ветку по умолчанию. Запуск в другой ветке только формирует отчёт. При отсутствии содержательных изменений коммит не создаётся. Сравнение по источнику и URL: изменения URL выглядят как удаление и добавление, обновления исходного кода JS при неизменных метаданных не отслеживаются. Правило пропуска источников без новых названий сохраняется, поэтому отчёт отражает результаты текущего сборщика, а не обязательно все записи каждой галереи.

Если источник недоступен или возвращает пустой каталог, сборка завершается ошибкой без публикации неполного результата. Если отдельный JS недоступен, используется прежний id из базы либо null, а список ошибок сохраняется в `fetch-errors.json` и отчёте. Это может сделать объединение расширений неточным; недоступный код в кэш не записывается. Публикация отменяется, если источник исчез или уменьшился более чем наполовину, каталог уменьшился более чем на 30% либо файлы несогласованны. Это не гарантирует выявление всех ошибок источников; проверяйте отчёты. Для работы workflow необходим доступ GitHub Actions к сайтам источников; в настройках репозитория должны быть разрешены Actions. Для записи в настройках Actions должно быть разрешено `contents: write`. JavaScript DashBlocks выполняется в отдельном задании только с доступом на чтение; публикация выполняется в отдельном задании с доступом на запись.
